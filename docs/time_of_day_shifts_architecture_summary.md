# Time-of-Day Shifts Architecture Summary\n\n## Project Context\n- **Backup Reference**: 11_20_13_A\n- **Date**: Current session\n- **Status**: Architectural design complete, implementation pending\n\n## Core Architecture Decisions\n\n### 1. Time-of-Day Status System\n**Based on docs/today_readme.md**:\n- 9 time-of-day statuses derived from sunrise/sunset\n- Dynamic boundaries: `startmorning = max(sunrise, 07:00)`, `endafternoon = min(sunset, 18:00)`\n- Status booleans: `isNight`, `isDawn`, `isMorning`, `isLight`, `isDay`, `isAfternoon`, `isDusk`, `isEvening`, `isDark`\n\n### 2. Shift Application Principle\n- **External factors act as modifiers, not absolute setters**\n- **Relative percentage shifts** applied to current parameter values\n- **No unshift mechanism** - clean state transitions between statuses\n- **Cumulative shifts** when multiple statuses active\n\n### 3. Configuration Files (Created)\n#### patternShifts.csv (135 lines)\n- 9 statuses × 15 LightPattern parameters\n- All zero values for Excel editing\n- Parameters: color_cycle_sec, bright_cycle_sec, fade_width, min_brightness, gradient_speed, center_x, center_y, radius, window_width, radius_osc, x_amp, y_amp, x_cycle_sec, y_cycle_sec\n\n#### colorsShifts.csv (72 lines)  \n- 9 statuses × 8 color parameters\n- Brightness + HSV shifts for primary & secondary RGB colors\n- Parameters: primary.brightness, primary.hue, primary.saturation, primary.value, secondary.brightness, secondary.hue, secondary.saturation, secondary.value\n\n### 4. Audio Architecture Extension\n#### Multi-Theme Box System\n- **Goal**: Activate secondary theme boxes alongside primary calendar theme\n- **Operation**: Theme box arithmetic (plus/minus directory lists)\n- **Selection**: Weighted random across 1-5 concurrent theme boxes\n\n#### Existing Weighted Random System (AudioDirector)\n- Directory selection based on `total_score`\n- Random ticket + cumulative score walk\n- File selection within directory using same method\n- Currently supports single theme box via `AudioPolicy::themeBoxDirs()`\n\n## Implementation Pipeline\n\n### Phase 1: Time-of-Day Status Detection\n**Location**: Extend TodayContext in ContextManager\n- Add 9 status booleans to TodayContext structure\n- Calculate status boundaries using PRTClock sunrise/sunset\n- Update on timer (10-minute intervals)\n\n### Phase 2: Policy Layer\n**New Classes**: TimeOfDayPolicy, ParameterShiftPolicy\n- Timer-driven status change detection\n- CSV configuration parsing using CsvUtils from Globals\n- Shift parameter application logic\n\n### Phase 3: Multi-Theme Audio\n**Modify**: AudioDirector, AudioPolicy\n- Support 1-5 concurrent theme boxes with weights\n- Theme box arithmetic: add/remove directory lists\n- Weighted random selection across multiple theme boxes\n\n### Phase 4: Integration\n**ConductManager**: New intents for shift application\n**ColorsStore/LightManager**: Shift application methods\n**AudioManager**: Volume parameter shifting\n\n## Architectural Constraints\n\n### Compliance Requirements\n- **Strict layering**: Boot → Plan → Policy → Conduct\n- **Intent-based routing** only, no direct parameter modification\n- **TimerManager** exclusively for timing\n- **Existing CSV parsing** patterns (semicolon delimiters)\n\n### File Locations\n- Configuration: ContextManager directory (moved from unauthorized /config/)\n- Code: Extend existing manager classes\n- No new directories without authorization\n\n## Key Technical Insights\n\n### CSV Structure\n- Semicolon delimiters (matching theme_boxes.csv)\n- Fully populated matrices with zeros\n- Excel-friendly for manual editing\n\n### Shift Mathematics\n- Multiplicative: `final_value = base_value * (1 + shift_percent/100)`\n- Cumulative for multiple active statuses\n- No state tracking between status transitions\n\n### Audio Multi-Theme\n- Directory list union operations\n- Clean add/remove tracking\n- Weighted selection probabilities\n\n## Next Implementation Steps\n\n### Immediate (Post-Reset)\n1.
